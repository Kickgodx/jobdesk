# Spec Delta

## MODIFIED Requirements

### Requirement: Схема базы обновляется при старте
API MUST при старте применять все миграции схемы ядра до последней под блокировкой Postgres: несколько процессов, стартующих одновременно, применяют их по очереди, и следующий видит уже готовую схему. Ошибка миграции SHALL останавливать старт, без создания таблиц в обход миграций; блокировка снимается и при ошибке. Схемы вынесенных сервисов мигрирует сам сервис (см. `platform/internal-services`).

#### Scenario: Миграция упала
- **WHEN** миграция завершилась ошибкой
- **THEN** API не стартует, блокировка миграций снята

### Requirement: Плановая очистка при старте и раз в час
При старте API и затем раз в час MUST выполняться очистка: архивирование вакансий (см. `catalog/vacancy-retention`), грейды HH (см. `sources/hh-sync`), а также служебные таблицы ниже. Кэш выдачи HH и историю HH sync очищает HH-сервис по тем же правилам и срокам. Очистку SHALL выполнять один процесс API из всех, работающих с этой базой (см. `platform/runtime-config`); если он завершился, её не позже чем через минуту берёт другой. Сбой очистки SHALL только записываться в журнал и не мешать работе API.

#### Scenario: Сбой очистки
- **WHEN** при старте очистка служебных таблиц упала
- **THEN** API стартует, в журнале предупреждение

#### Scenario: Несколько процессов API
- **WHEN** API запущен с `API_WORKERS=4`
- **THEN** очистка при старте выполнилась один раз, а не четыре

#### Scenario: Процесс-исполнитель завершился
- **WHEN** процесс, выполнявший очистку, упал, а остальные процессы API работают
- **THEN** не позже чем через минуту очистку выполняет другой процесс

#### Scenario: HH-сервис остановлен
- **WHEN** HH-сервис не запущен, а API выполняет плановую очистку
- **THEN** очистка ядра выполняется полностью, кэш выдачи HH не меняется

### Requirement: Завершённые задачи удаляются по сроку хранения
Завершённые LLM-задачи MUST удаляться через `retention.llm_jobs_ttl_days` (30) суток после завершения, завершённые прогоны и HH sync — через `retention.parse_runs_ttl_days` (180); без времени завершения срок считается от создания. HH sync удаляет HH-сервис при старте и раз в час. Активные задачи SHALL NOT удаляться. Вакансии, оценки и письма остаются. `0` хранит всегда.

#### Scenario: Старые и свежие задачи
- **WHEN** есть LLM-задачи `done` 40 суток назад, `error` без времени завершения, созданная 40 суток назад, `done` 5 суток назад и `running` 40 суток
- **THEN** удалены первые две, `done` 5 суток и `running` остаются

#### Scenario: Срок 0
- **WHEN** `retention.llm_jobs_ttl_days: 0` и `retention.parse_runs_ttl_days: 0`
- **THEN** задачи и прогоны любого возраста остаются

#### Scenario: Старый HH sync
- **WHEN** HH sync завершился 200 суток назад, `retention.parse_runs_ttl_days` 180
- **THEN** после очистки HH-сервиса записи этого sync нет
