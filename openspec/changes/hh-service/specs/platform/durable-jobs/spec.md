# Spec Delta

## MODIFIED Requirements

### Requirement: Режимы rq и inprocess взаимозаменяемы
Каждый тип задачи MUST выполняться одинаково в режиме `rq` (очередь Redis, отдельный воркер) и `inprocess` (поток в процессе, принимающем задачу: API для прогона и LLM-задач, HH-сервис для HH sync). В `inprocess` восстановление MUST работать в этом процессе и при его старте сразу ставить заново оставшиеся `queued`; в `rq` восстановление живёт в воркерах, и старт API или HH-сервиса его SHALL NOT запускать.

#### Scenario: Старт API в inprocess
- **WHEN** API стартует в `inprocess`, а в БД остался прогон в `queued` от прошлого процесса
- **THEN** прогон ставится в работу без ожидания порога «зависшей» задачи

#### Scenario: Старт API в rq
- **WHEN** API стартует с бэкендами `rq`
- **THEN** API не восстанавливает задачи сам

#### Scenario: Старт HH-сервиса в inprocess
- **WHEN** HH-сервис стартует с `HH_SYNC_JOB_BACKEND=inprocess`, а в его схеме остался sync в `queued`
- **THEN** sync ставится в работу без ожидания порога «зависшей» задачи, API ядра его не трогает
