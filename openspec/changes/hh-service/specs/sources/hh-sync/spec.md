# Spec Delta

## ADDED Requirements

### Requirement: HH sync выполняет HH-сервис
Поиск, детали, дедуп, кэш выдачи и джобы HH sync MUST принадлежать HH-сервису; вакансии он SHALL читать и записывать только через внутренний API ядра (см. `platform/internal-services`). Публичные `/api/v1/hh/*` сохраняют пути, тела и коды ответов. Рестарт ядра SHALL NOT прерывать выполняемый sync.

#### Scenario: Рестарт ядра во время sync
- **WHEN** sync загружает детали, и процесс API ядра перезапускается
- **THEN** sync продолжается и завершается `completed`, ход sync снова виден через `/api/v1/hh/sync-jobs/{id}`

#### Scenario: Ядро недоступно для записи
- **WHEN** во время sync внутренний API ядра не отвечает при записи пачки
- **THEN** sync завершается `failed` с причиной в `error_message`, записанные ранее пачки остаются в базе

## MODIFIED Requirements

### Requirement: Кэш выдачи HH очищается по сроку
После успешного sync, а также при старте HH-сервиса и раз в час, строки кэша выдачи, не встречавшиеся в выдаче `hh.listing_ttl_days` (40) суток, MUST удаляться; для таких вакансий детали скачаются заново. `0` SHALL отключать очистку.

#### Scenario: Давно не встречалась
- **WHEN** вакансия не встречалась в выдаче больше 40 суток
- **THEN** её строка кэша выдачи удалена, сама вакансия остаётся в каталоге
