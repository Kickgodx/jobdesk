# Proposal

## Why

Сверка промптов (`jobdesk/ai/prompts.py`) с тем, что им реально приходит, нашла места, где модель
ошибается без явных сбоев:

- «Спросить базу»: в фактах есть `unrecognized_filters`, `count.active` и неполный текущий месяц
  в `trend`, но промпт ответа о них не знал. Ответ мог выдать цифры по более широкой выборке как
  отфильтрованные, назвать вакансии за всю историю открытыми и увидеть «обвал» в месяце, который
  ещё идёт.
- Извлечение: поля `company`, `contact`, `required_experience`, `employment_type` есть в схеме
  ответа, но не описаны. `company` в `primary` идёт в `company_key` (дедуп, топ и новые компании
  обзора), а занятость приходила свободным текстом при значениях правил `full-time` / `part-time` /
  `contract`. Few-shot противоречили правилам (грейд «Engineer II», роль «AI/frontend») и содержали
  бессмысленную фразу в `notes`.
- Матчинг: по-русски требовалось только `explanation` — у английской вакансии `strengths`, `risks`
  и `evidence` приходили по-английски; футер канала мог читаться как требования.
- Обзор: `avg_4w_vacancies`, `with_salary_share` и `sources` не были описаны.

## What Changes

- `ask-market-v2`: правила для `unrecognized_filters`, `count.vacancies` / `count.active`, месяца
  `partial`, `lifetime` только по Telegram; backend помечает текущий месяц тренда `partial: true`.
- `extract-v12`: правила для компании (наниматель, не канал; агентство → клиент), контакта, опыта,
  занятости; исправлены few-shot. Схема приводит `employment_type` LLM к `full-time` /
  `part-time` / `contract`, прочее — `null`. Пять golden-кейсов с фикстурами.
- `match-v3`: все текстовые поля по-русски, футер канала — не требования.
- `market-digest-v3`: объём сравнивается и с прошлой неделей, и со средним за 4 недели; описаны
  доля с зарплатой и источники.

## Capabilities

### Modified Capabilities

- `catalog/ask-market` — флаг неполного месяца, правила ответа.
- `catalog/market-digest` — правило объёма в промпте.
- `ingestion/ai-extraction` — компания и занятость из ответа LLM.
- `career/resume-matching` — язык текстовых полей оценки.

## Impact

Без миграции. Смена версий: кэш extraction для новых постов промахивается (посты прогонов идут в
LLM заново, сохранённые вакансии не трогаются); сохранённые оценки и обзоры становятся `stale` и
пересчитываются при следующем запросе без `force`. `employment_type` вакансий HH не менялся
(названия HH: «Полная», «Частичная»).
